# Theme reference

A theme is a folder: `~/.config/harv/themes/<id>/theme.toml` (+ optional `style.css`, `fonts/`). Install one with
Preferences → Theme → *Install from folder / .zip*, or `harv --install-theme <folder|.zip>`. Check one with
`harv --validate-theme <id|folder>` (parses, resolves `extends`, loads every variant in both schemes, warns about low contrast).
Editors: `#:schema ../../docs/theme.schema.json` on the first line of `theme.toml` gives completion (Taplo / Even Better TOML).
A working example is in `docs/examples/catppuccin/`. Layout (`[shell]`, `[page.*]`) and `[lyrics]` are described in `THEMING_DESIGN.md`.

## Smallest theme

```toml
[meta]
name = "Mine"
extends = "blur"     # inherit every key you don't set
scheme = "dark"
[colors]
derive = true
bg = "#101418"
fg = "#e6edf3"
accent = "#58a6ff"   # or "cover" to follow the artwork
```

## `[colors]`

Formats: `#rgb`, `#rrggbb`, `#rrggbbaa`, `rgb()`, `oklch(L C h)`.

| Key | Used for |
|---|---|
| `bg`, `sidebar`, `raise`, `hover` | page, sidebar, popups/cards, hover rows |
| `fg`, `dim` | text, secondary text |
| `accent`, `accent_on` | accent (or `"cover"`), text on it |
| `play_bg`, `play_fg` | play buttons |
| `bar_bg`, `bar_fg` | bottom player bar |
| `toast_bg`, `toast_fg` | toasts |
| `np_fg`, `np_on` | full-screen lyrics page text / play-button icon (sits on the cover backdrop) |
| `line`, `selected`, `focus`, `scrim`, `danger`, `success`, `warn` | extras for your `style.css` as `@line` …; always defined, derived when omitted |

**`derive = true`** (in `[colors]`): with `bg` and `fg` set, every key you leave out is computed (OKLab mixes of bg/fg, readable text on the accent) instead of inherited from `extends`. If there is no `[colors_alt]`, the opposite-scheme palette is generated by flipping bg/fg lightness (hue and accent kept). Give a `[colors_alt]` with its own `bg`+`fg` to take control of it.

## Variants

```toml
[variants.latte]
name = "Latte"
scheme = "light"          # optional; otherwise decided by the background's lightness
[variants.latte.colors]   # same keys as [colors]; missing ones derive from its bg/fg
bg = "#eff1f5"
fg = "#4c4f69"
[variants.latte.colors_alt]   # optional; generated when absent
```

Pick one from the palette menu on the theme's card. The choice is remembered per theme.

## Numeric tokens

| Table | Keys |
|---|---|
| `[shape]` | `xs sm md lg input xl control cover hero` (px radii, `control` 9999 = pill) |
| `[metrics]` | `sidebar_w track_row_h label_tracking border_w` (hairline width, 0 = none) |
| `[effects]` | `ambient bar_tint` (cover wash 0..1), `shadow` (drop-shadow multiplier, 0 = flat), `motion` (duration multiplier, 0 = instant) |
| `[vars]` | your own: `glow = 0.35` → `{{glow}}` |

## `style.css`

Appended after the app stylesheet. It is templated like the app's own CSS:

- `{{r_md}}` `{{r_lg}}` … radii, `{{border_w}}`, `{{sidebar_w}}`, `{{track_row_h}}`, `{{font_ui}}`, `{{font_mono}}`, plus your `[vars]`.
- `{{c_bg}}` `{{c_fg}}` `{{c_accent}}` (fixed accents only) … every colour as a literal, for places `@name` cannot go.
- `{{shadow:0.4}}` → that alpha × `effects.shadow`; `{{ms:150}}` → `150ms` × `effects.motion`.
- GTK named colours: `@bg @bg_side @bg_raise @bg_hover @fg @fg_dim @accent_on @play_bg @play_fg @bar_bg @bar_fg @toast_bg @toast_fg @np_fg @np_on @lib_accent` and the extras above.
- `/* comments */` are removed before substitution, so a `{{` inside one is harmless.

## Material 3 palette generator (`[material]`)

```toml
[material]
seed = "cover"            # "cover" = follow the playing artwork (regenerated on every track), or a colour such as "#6750a4"
variant = "expressive"    # tonal-spot (default) | vibrant | expressive | neutral | fidelity
```

Generates `[colors]` and `[colors_alt]` from the seed: the M3 roles for light and dark, mapped onto the tokens
(`bg` = surface, `sidebar` = surface-container-low, `raise` = surface-container-high, `hover` = surface-container-highest, `fg` = on-surface,
`dim` = on-surface-variant, `accent` = primary, `bar_bg` = surface-container, `toast_*` = inverse-surface, `line` = outline-variant,
`selected` = secondary-container, `surface_1..5` = the five containers). Keys you set yourself in `[colors]` win over the generated ones.

- All roles are also available as `@m3_<role>` (`@m3_primary`, `@m3_on_secondary_container`, `@m3_surface_container_high` …) and `{{c_m3_<role>}}` in your CSS.
- With `seed = "cover"` the whole scheme is regenerated whenever the cover colour changes, and when the user picks a fixed accent in Preferences that colour becomes the seed. Colours you override in `[colors]` apply to the static fallback scheme only; while the scheme is being regenerated the generated values are used.
- The Rust side (theme gallery swatches, `harv --validate-theme` contrast checks) sees the fallback palette (seed `#6750a4`), not the cover-driven one.
- **This is an approximation of Material Color Utilities**: tones are OKLCH lightness steps and chroma is scaled into OKLCH and gamut-mapped. Hues and contrast follow the spec closely; exact hex values do not match Google's generator.
- A `[variants.<id>.material]` table switches seed and / or flavour for that variant.
- Full-screen lyrics: the generated `np_fg` / `np_on` are on-surface / surface, so use `[lyrics] backdrop = "gradient"` (or `solid`), not `cover`.

## State layers, type, motion

| Token | Meaning |
|---|---|
| `{{st:0.08}}` | A hover / press / selected overlay alpha times `[effects] state` (default 1). The app CSS uses it for every state-layer alpha. |
| `{{fs:13}}` | `13px` times `[type] scale`. |
| `{{fw:600}}` | `600` plus `[type] weight_shift` (clamped 1–1000). Variable fonts take any value. |
| `{{type:title_large}}` | A whole role: `font-size`, `font-weight`, `letter-spacing` (+ `font-variation-settings` when the role has `width` / `axes`). Roles are the 15 M3 roles (`display_*`, `headline_*`, `title_*`, `body_*`, `label_*`); override per role with `[type.<role>]` (`size`, `weight`, `tracking`, `width`, `axes`) or add your own. |
| `{{ease:spatial}}` | An easing curve by name. Defaults: `ease ease_in_out ease_out ease_in pop` (what the app CSS used), plus `standard emphasized spatial effects bounce` (overshooting for `spatial` / `bounce`). Override any in `[motion]`; any other name you define works too. |
| `{{surface_1..5}}` | The surface ramp as `@surface_1` … `@surface_5` colours (lowest to highest). Derived from bg/fg unless set (or generated by `[material]`). |

`{{ease:…}}` and `{{ms:…}}` only change what the app CSS asks for; they have no effect on animations done in code (the lyrics view).

## Shapes per component

```toml
[shape.component]   # radii in px; fallbacks in brackets
button = 12         # pill buttons, .pill-btn            (control)
card   = 28         # cover cards                        (xl)
play   = 20         # play buttons: 999 = round, 20 = rounded square   (999)
chip   = 12         # filter chips                       (control)
search = 28         # search fields                      (input)
nav    = 16         # sidebar rows                       (md)
[shape.pressed]     # same keys: the radius while pressed (shape morph, animated with {{ease:spatial}})
play = 28
```

`{{r_btn}} {{r_card}} {{r_play}} {{r_chip}} {{r_search}} {{r_nav}}` give the resolved values to your own CSS.

## Layout additions

- `[shell.sidebar] item_style = "rail"`: a Material navigation rail (icon in a pill indicator, label underneath; section titles are skipped). Use `sidebar_w = 80..96`.
- Bottom-bar `transport`: `play = "rounded"` (rounded-square button, radius `shape.component.play`) and `group = "connected"` (the buttons share one segmented group; pressed segments become fully round).
- Bottom-bar `seek`: `style = "wavy"` (`wave_amp`, `wave_len`, `wave_stroke`, `wave_height` in px). The wave travels only while playing; paused, nothing runs.

## Shell options

```toml
[shell.sidebar]
position = "right"      # left | right
collapse = "always"     # auto (icons in narrow windows) | always (icons only) | never
[shell.bottom_bar]
position = "top"        # bottom | top
[shell]
panel_side = "left"     # side of the page used by [page.*] right panels: right | left
```

Not configurable: the breakpoint widths (1100 px hides the right panel, 940 px collapses the sidebar). libadwaita breakpoints can't be changed after the window exists.

## Themeable Home and Artist pages

`[page.home]` and `[page.artist]` work like the other page kinds (`main`, `right`, `right_w`). With no `main`, the built-in page is used.

| Component | Where | Meaning |
|---|---|---|
| `heading` | any page | A page title: `word` (vocabulary key) or `text`; defaults to the page's own title. `sub` adds a subtitle line. |
| `shelf` | home, artist | One shelf, chosen by `key` (`recent`, `favorites`, `yt:0`, `yt:1` … on Home; `albums`, `singles` on Artist), `title` or `index`. |
| `shelves` | home, artist | Every shelf not placed yet, in order. `skip = ["recent"]` leaves some out, `only = [...]` picks some. |

Both shelf components take `style = "row"` (scrolling row, default) or `"grid"` (wrapping, `columns = 5`), `limit` (cards), `title = false` and `gap`.
An artist page also takes `hero` (use `shape = "round"`) and `track-list`. A shelf is placed once: `shelf` / `shelves` skip shelves an earlier component already placed.
The Home error state (YouTube Music could not load) is appended below whatever layout you build. See `docs/examples/layout-showcase/`.

## Cover-driven colour

For `[material] seed = "cover"` themes the stored theme (what the lyrics page and the theme gallery read) is regenerated together with the stylesheet on every cover change, so swatches and the full-screen lyrics colours follow the artwork. `harv --validate-theme` lints twelve sample seed hues in both schemes, not just the fallback seed.
